# CLAUDE.md — research-jobs

Read this first, then README.md and CONVENTIONS.md.

## The job

Build a directory of every small research lab in the Boston / Cambridge area, with a real contact for each.
"Small" = 10 or fewer current members (PI included). A lab is worth recording at any size; small ones are the point.

The target list is done (`data/targets.csv`, 638 rows). Your job is the **scraper**: visit each target, find its labs (or, for think tanks and policy centers, its research staff and careers page), and write the results in the existing schema. Run on this Mac with Playwright so pages that need JavaScript render.

## Repo layout

| Path | What |
|---|---|
| `data/targets.csv` | Where to scrape. One row per department, center, institute or think tank: `start_url`, `people_url`, `careers_url`, `priority`, `collect`, `status` |
| `data/sources/<target-id>.json` | Your output: one file per target (schema below) |

| `scripts/merge_discovery.py` | Folds discovery CSVs into targets.csv |

## Source file schema (`data/sources/<target-id>.json`)

```json
{
  "id": "mit-chemistry",
  "institution": "MIT",
  "unit": "Department of Chemistry",
  "city": "Cambridge, MA",
  "checked_on": "YYYY-MM-DD",
  "listing_urls": ["https://chemistry.mit.edu/faculty/"],
  "labs": [ { ...lab... } ],
  "non_lab_people": [ {"name": "", "title": "", "email": "", "why": "teaching role / emeritus, no group / member of X lab"} ]
}
```

Lab object (null when not shown on a page — never guess):

`id` (`<target-id>-<pi-first-last>`, kebab-case), `kind` (`research-lab` | `core-facility`), `lab_name`, `pi_name`, `pi_title`, `pi_email`, `accepting_grad_students` (true/false/null, only if stated), `lab_website`, `location`, `phone`, `admin_name`, `admin_email`, `research_summary` (one sentence, own words), `member_count` (current members incl. PI, alumni excluded), `member_breakdown` (e.g. "1 PI, 3 postdocs, 5 grad students, 1 admin"), `members_page_url`, `join_page_url`, `join_notes` (how to apply, whom to email), `profile_url`, `notes` (what couldn't be read and why).

Existing files to match: `data/sources/harvard-chemistry.json`, `harvard-mcb.json`, `ragon.json`.

## Rules

1. **Record only what a page shows.** No invented emails, URLs or counts. Unknown is null; say why in `notes`.
2. **Folder and file names are lower kebab-case.** No spaces, capitals or underscores.
3. **Be polite:** one request per second per host, a real User-Agent naming the project, honour robots.txt. If robots.txt blocks a site, record that in `notes` and move on.
4. **Cache raw HTML** under `cache/` (gitignored) so reruns don't refetch.
5. **Update a target's `status`** in `targets.csv`: `todo` → `partial` → `done`.
6. **Push early and often.** After every target (or every batch of small ones, and at least every 30 minutes of work): `python3 scripts/build.py`, update the Coverage table in README.md, then `git add -A && git commit && git push`. The owner watches progress on GitHub, so unpushed work is invisible work. Commit messages say what was added and the new totals (labs, emails, small labs).
7. **Code is part of the repo.** All scraper code lives in `scripts/` and is committed and pushed with the data it produced, including parsers, helpers and any one-off scripts used to make a source file. Nothing that produced data should live only in `/tmp`, a scratch folder or a subagent's workspace. `cache/` stays gitignored.
8. **Only the main session runs git.** Subagents or forks write files and report back; they never run `git add/commit/push` or `scripts/build.py`. The main session reviews, builds, commits and pushes.
9. Do not delete or rewrite earlier source files except to fill nulls with better data.

## Order of work

1. `data/to-read.txt`: fill `member_count`, `join_*`, emails for labs already in `data/sources/` (Harvard Chemistry, Whitehead, Ragon, MCB, MIT Chemistry).
2. `targets.csv` priority 1 (science and AI units with PI-led labs), institution by institution: Harvard, MIT, Broad/Whitehead/Ragon/Wyss/Koch/McGovern/Picower/Kempner, BU, Northeastern, Tufts, Brandeis, BC, UMass Boston, hospitals.
3. Priority 2 (policy centers, business, law, education, design). For think tanks and policy centers the "lab" is the organization or program; collect research leads, staff page and careers/RA/internship page.
4. Priority 3 last.

Write the scraper as reusable pieces in `scripts/` (e.g. a fetcher with cache + rate limit, per-site-family parsers for common platforms: Harvard Drupal "hwp" people pages with facet filters, MIT WordPress faculty pages, BU/Tufts directory pages, Wix/Squarespace/Google Sites lab pages). Most of the work is people pages, so a generic "find the people/team/members link, count names under current-member headings, stop at 'Alumni'/'Former'" parser goes a long way. Spot-check counts by eye on a sample.

## Known gotchas

- **http↔https redirect loops:** arp.harvard.edu (Anderson), csail.mit.edu, mcgovern.mit.edu, cis.mit.edu, aeroastro/meche/idss/lids/imes/energy.mit.edu homepages, cba.mit.edu, cshub, smart.mit.edu, Tufts Physics, fic.tufts.edu, csdd.tufts.edu, BU Cancer Center. Try the http URL directly and subpages.
- **JS-rendered:** Northeastern engineering department sites (bioe, che, cee, ece, mie), several Brandeis and Heller pages, Rosenstiel, Volen, MRSEC. Use Playwright.
- **robots.txt blocks:** Jacobsen group (now jacobsengroup.sites.fas.harvard.edu), seis.northeastern.edu, RLE /people.
- **Obfuscated emails:** Ragon lab pages. Some decoded addresses are in `notes` as "Unverified"; confirm by rendering the page.
- **Bot protection:** childrenshospital.org (use research.childrenshospital.org). Several self-hosted `*.wi.mit.edu` Whitehead Institute lab sites (not the Squarespace/Wix/Webflow ones) return a 403 "Robot Challenge Screen" to any automated fetch, with or without JS rendering: hrvatinlab, jaenischlab, louridolab, weinberglab, reddienlab, yamashitalab, hamilos. Don't try to bypass it; record the block in `notes` and move on. `arp.harvard.edu` (James Anderson) also returns an Akamai "Access Denied" regardless of protocol or user-agent, separate from its http↔https loop. The same Akamai "Access Denied" (not robots.txt, not UA-based — confirmed with both plain HTTP and headless Chromium) also blocks many personal-site subdomains from this network: `perrimon.med.harvard.edu`, `cluzel.fas.harvard.edu`, `projects.iq.harvard.edu/gaudetlab`, `hekstralab.fas.harvard.edu`, `hoekstra.oeb.harvard.edu`, `projects.iq.harvard.edu/kleckner_lab`, `projects.iq.harvard.edu/kuneslab`, `lichtmanlab.fas.harvard.edu`, `murraylab.fas.harvard.edu`, `projects.iq.harvard.edu/prigozhin`, `projects.iq.harvard.edu/uchidalab` — while centrally-hosted Harvard sites (`cbs.fas.harvard.edu`, `hscrb.harvard.edu`, `*.mcb.harvard.edu`) work fine. May need a different egress network to fix; don't try to bypass it, just record the block and move on. `faculty.chemistry.harvard.edu/kni` (Kang-Kuen Ni) is the same pattern. As of 2026-10-28 it also blocks these whole domains outright (every page, including the homepage): `physics.harvard.edu`, `psychology.fas.harvard.edu`, `sociology.fas.harvard.edu`, `statistics.fas.harvard.edu`, `origins.harvard.edu`.
- **Paginated listings:** BU centers directory (`?num=2..14`), Northeastern institutes ("Load more"), DUSP labs (`?page=1`), Harvard Drupal people pages (`?page=N`), Shakhnovich people (2 pages).
- **Counts:** Harvard MCB counts came from the department directory filtered by lab and include shared admins. Rowland counts = PI + directory staff naming the lab (may undercount). Heller (Harvard Chem) shows "Current Members (6)" but not who.
- **Moved / renamed:** HBS Digital Data Design Institute → HBS AI Institute (aiinstitute.hbs.edu); ucsusa.org → ucs.org; Center for Global Change Science → cs3.mit.edu; quest.mit.edu → sqi.mit.edu. Jeffrey Long's profile still links his Berkeley site (and that old Berkeley site itself now times out — his Harvard lab's own site/contact info is unread). Beacon Hill Institute looks inactive (nothing after 2015).
- **MIT Chemistry department profiles are a reliable source:** `chemistry.mit.edu/profile/<slug>/` pages reliably show pi_email, phone, office location, shared admin contact, "accepting grad students" and a direct link to the PI's own lab site — fetch the profile first, then follow the link for member counts/join info.
- **SPA fallback (always 200):** `chemistry-buchwald.mit.edu` returns identical 200-OK content for every guessed path (`/people`, `/team`, `/group`, ...), so you can't find its real roster route by probing status codes; needs a real browser click-through or a sitemap.
- **Co-advised students:** at MIT Chemistry, several students/postdocs are co-advised across labs (e.g. Roman/Surendranath/Shao-Horn/Radosevich/Kulik) — each lab's own roster page counts them, so overlap in `member_count` across those labs is expected, not a double-counting bug.

Also: Harvard SEAS's faculty directory (`seas.harvard.edu/faculty?page=%2CN`, 10 pages of 20, static HTML with full name/title/email/phone/office) and Wyss Institute's team pages are discoverable even though their landing pages (`/faculty`, `/team/`) look JS-only -- SEAS via its pagination query param, Wyss via its WordPress taxonomy sitemap (`sitemap-tax-team-category.xml` -> `/team/core-faculty/`, `/team/associate-faculty/`, etc.). When a directory page looks like an empty JS filter shell, check `<site>/sitemap.xml` for a `sitemap-pt-person-*` or `sitemap-tax-*-category.xml` entry before giving up. Also: cross-cutting hubs (CMSA, HDSI, Salata, and part of CBS) mostly list faculty whose real lab lives in their home department -- don't duplicate those entries, just note the cross-reference and leave the hub's own `labs` list thin.
